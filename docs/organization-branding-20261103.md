# 2026-11-03 组织通讯与品牌配置

本轮基于固定 OpenIM 3.8，账号、个人资料与访问权限仍由 GoSuxin / HRM 管理。内网入口使用 `https://192.168.10.11:9880`（HRM）和 `https://192.168.10.11:9885`（IM），公网分别使用 `hr.szputy.com:9880`、`im.szputy.com:9885`。

## 使用方式

- 添加好友、全局人员搜索与组织架构支持员工姓名、明确工号、手机号。搜索只返回当前允许访问的企业人员；手机号用于匹配，不在组织目录公开返回。停用、离职、撤权人员及其他企业人员不会因该搜索获得通讯权限。
- 同一企业中具备通讯权限的同事可直接发起会话，无需先成为好友。此规则保留黑名单、接收设置和会话撤权检查。
- PC / 网页、Android / iOS 共享源码新增组织架构入口，可展开部门、查看人员资料及发消息。
- 部门管理在“状态”后增加“部门群”，并支持部门负责人。默认关闭；开启前必须选择有效负责人。开启后自动维护部门成员，负责人变更会移交群主。关闭后停止自动维护，保留原群、成员与聊天记录。
- 通讯管理增加姓名/工号/部门/原因、部门、启用状态和同步状态筛选。“使用此记录”已改为“填入操作表单”：只填入选中记录，后续仍需执行具体操作按钮。
- HRM 插件左上角图标限制为 40 × 40，避免占据宽幅空间。

## 品牌与图片配置

构建时显示名与安装包名称统一配置于 `clients/brand.json`：`displayName` 为 `PUTY内部通讯`，`technicalName` 为 `PUTY_IM`。运行时应用界面名称读取通讯后台的 `appName` / `webTitle`；登录前也可取得公开显示配置。操作系统安装名称、桌面快捷方式及程序文件名需修改构建配置后重新打包，运行时配置不重命名已安装的系统条目。

客户端修改构建名称后运行 `python clients/tools/sync_brand.py`，核对可用 `--check`。应用 ID、Android 签名和 Windows 原用户数据目录保留。

五份透明 PNG 为 `E:\suxinlogo\IM.png`、`HR.png`、`Suxin.png`、`OA.png`、`小工具.png`。本轮使用内置图像编辑工具，仅去除图标外部黑角，保留蓝色图标、文字与徽标；原文件在同目录 `backup-before-transparent-20261103`。处理提示与前后 SHA-256 记录于 `assets/brand/transparent-20261103.json`，项目源副本位于 `assets/brand/source`。`LOGO2.png` 原文件不变，继续作为默认头像。

HRM 通过 `scripts/generate-brand-assets.py` 生成部署图标；客户端图源位于 `clients/branding`。当前使用的网页 logo 和 favicon 均为 PNG；Windows / macOS 系统图标格式由 PNG 派生为 ICO / ICNS。OA 与小工具目前没有已启用模块引用，保留相应透明源素材供模块使用。

## 验证与边界

真实合成账号已验证六项姓名/工号/手机号精确查询、权限范围与部门条件组合、未添加好友的双向 WSS 消息及原生持久化历史。优化后六次精确查询耗时为 107–148 毫秒；该数据为本次内网实测。

部门群已验证默认关闭、无负责人拒绝开启、开启自动建群、群主随负责人转移、关闭后群和成员保持。合成部门群保留审计记录，不作为真实业务部门。

Web / Windows 完成构建、回归和实际客户端验证。Android 使用同正式签名的 x64 包在 API 30 验证正常主入口，ARM64 包独立核对签名、包名、ABI、根证书与固定 SDK；模拟器结果不代表 ARM64 真机媒体验收。iOS 同步共享源码、名称与图标，本机没有 Mac / Xcode 签名构建条件。

用户已确认两个公网登录页可以打开。内网连接公网 SNI 的 TLS 检查不代表路由器外网媒体端口或 NAT 已完成验收。本轮不改写既有媒体测试的失败与未验收记录。

最终安装包、版本和校验值以 `clients/artifacts-manifest.json`、`clients/artifacts.sha256` 为准；测试原始报告和部署回执保存在受限的 `.private/production/acceptance`。

## 3.8.10 附件、图片授权与目录修复

超过 5 MiB 时，固定 SDK 改走带 SigV4 请求头的分片上传。原附件代理删除了该签名，导致普通文件、视频及较大图片失败；这不是 5 MiB 发送上限。代理现只在当前有效 SID、精确写 grant、上传权限及固定分片协议全部通过后转发 MinIO 所需的三个签名头，存储服务继续验签；下载和头像不透传调用者凭据。两个入口仅补充相应 CORS 头，原 origin 白名单不变。

Web / Windows 3.8.10 按当前查看者重新授权聊天、工作圈、引用大图、图库及播放器资源，隔离账号和 SID 缓存，拒绝迟到的旧会话响应；自动失败刷新限一次，随后显示可重试状态。工作圈发布时不再向已签名 URL 拼接额外缩略参数，已有临时链接通过重新授权读取。核对的两名真实员工权限相同，相关四个存储对象 HEAD 均为 200 且大小匹配；未代登真实账号，未修改原消息或动态。

组织目录改为请求内两次批量实时校验，保留当前账号、密码指纹、HRM 状态、角色权限及企业范围判断。62 人回归含 5 个即时排除，SELECT 由 593 次降至 18 次，八类并发状态变更均按实时资格处理。真实大企业范围的可选只读性能探针因数据库只读变量不兼容而保护拒绝，未据此宣称大范围实测耗时。独立测试范围两人，Web 三次组织页加载 220–265 毫秒，PC 218–276 毫秒。

正式 Node 22.23.4 的 144 项代码回归、6 项浏览器保护图片交互和 TypeScript 均通过。上线网页及打包 PC 正常主入口各完成 11 类合成附件、损坏视频无上传提示和三次组织页往返；收件人从原生历史验证 30 条消息，对 11 份不同文件完成全量 SHA-256 和 206 字节范围校验。PC 完整套件部分命中内容去重；真实大视频分片 PUT 已由修后旧包独立验证，不把去重当重复传输证明。本轮未重跑 NSIS 覆盖安装，Android 包与既有 ARM / iOS 验收边界不变。

## 部门群周期同步与管理员权限修复

部门同步原来每轮都会调用改名、关闭全体禁言接口，即使名称完全相同，也产生 `imAdmin38` 操作通知并覆盖群内禁言决定。现在保留周期检查和真实名称、成员、负责人漂移修复；名称相同时不调用改名接口，同步不再修改全体或个人禁言，已有管理员角色保持。真实部门改名仍同步一次，响应丢失后的重试不重复通知。

当前部门群主可将已入群的其他成员设为管理员或撤销为普通成员。服务端先确认当前原生群主和目标成员，普通成员、管理员及未入群用户不能代为授权；成员加入、移出和群主变更继续由 HRM 管理，不能借此接口改资料或转移群主。

Go 1.25.14 的 group、enterprise 两包测试与 vet、独立复核和发布工具 13 项离线回归通过。覆盖群主实际角色写入、17 类拒绝且零写入、同版本检查、管理员与禁言保持、真实漂移修复、失败重试。仅更新 `enterprise-service` 和 `openim-rpc-group`，Web / Windows 继续使用 3.8.10，无需重新安装；未代登真实员工或更改真实业务群的成员、角色及禁言来测试。

市场部只读观察：修复前约 3 分钟内，自动改名和关闭全体禁言各 6 次；修复后连续约 156 秒，两类通知均为 0。同步任务仍有新的成功处理时间，版本一致且无错误；该群群主、6 名成员、角色和禁言状态保持。24 个生产容器运行正常，HRM 主程序、客户端发布清单、入口配置和启用时间未变。原有历史通知保留。
