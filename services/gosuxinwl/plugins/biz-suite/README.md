### 0.3.0 本地考勤重建与简化

- 日常通过“考勤设置 → 考勤明细与异常 → 月度考勤”操作。保存并生效自动生成派生排班及后台核算；复核、月结和导出仍校验权限、数据完整性与锁定状态。
- 月度页面按月展示本地日结果，分别汇总实际工时、核定出勤及工作日/休息日/节假日加班。一键月结自动提交整月计算，展示进度后执行完整性检查及月结；关闭进度窗口不继续锁定，计算仍保留。当前或未来月份、待配置及未复核结果不能月结。
- 每个采证段独立配置精确到秒的上下班窗口，支持前日、当日、次日。后台显示可取卡的最早和最晚秒值，计算时转换为半开区间；相邻事件不得复用同一卡。表格未明确的窗口留空，批量填写后才能生效，未配置显示“待配置”。
- 工作簿的三个分类独立导入，来源单元格可追溯。品质部按本次确认的三组人员生成不同草稿；邢玉琴、杨玛玲无晚间加班17:30结束，有加班17:15结束、17:45返岗、18:00起计晚间加班。
- 正班核定、实际工时和加班分别记录；支持完整班8小时、注塑固定30分钟扣休、分切连续采证与工时分段、生产职员晚间最多2小时、大小周及晚走晚到。缺卡、班次歧义及未知扣减进入复核，不根据企业微信原标签判断。
- 企业微信考勤规则接口与导入已停用，旧快照仅留审计。自动同步只在08:30、10:00、14:30、23:59启动通讯录、原始打卡和审批任务。
- 本次历史修订起点为2026-10-01，旧制度与结果保留；8、9月核定基准不改。使用维护工具的 `--rebuild-local-rules --actor <管理员ID>` 只建立待确认草稿并停用旧来源制度；`--recalculate-start 2026-10-01 --recalculate-end YYYY-MM-DD` 仅提交本地计算。不会补造打卡窗口、恢复被过滤人员或请求企业微信规则。

### 0.2.3 企业微信每日四次自动同步

## 配置和运行

在 **企业微信 → 同步控制台** 填写企业 ID、通讯录读取 Secret，以及打卡/审批自建应用 AgentID、Secret。通讯录读取槽可填写有相应读取权限的自建应用 Secret，两个槽按用途区分；通讯录请求只使用通讯录读取凭据；打卡、请假、外出、出差统一使用自建应用凭据，不会跨通道自动回退。

两个 Secret 均为只写字段：留空保留已保存值，明确勾选清除才删除保存值并回退服务器环境。保存后立即生效且输入框清空；GET 设置、状态、诊断均不返回 Secret 或 Token。保存和检查连接需 `biz-suite.wecom.manage`。

可选环境变量（设置于 **GoSuxin 宿主进程**，修改后需重启宿主）：

```text
WECOM_CORP_ID
WECOM_AGENT_ID
WECOM_CONTACT_SECRET
WECOM_APP_SECRET
```

网页保存的 Secret 优先于环境值。旧 `WECOM_SECRET` 仅作为自建应用 Secret 的兼容别名，绝不会替代通讯录 Secret；旧 `WECOM_CHECKIN_SECRET`、`WECOM_APPROVAL_SECRET` 不再分流，界面提示迁移到 `WECOM_APP_SECRET` 或网页自建应用配置。

通讯录 Secret 的详细读取权限因企业环境而异，新环境可能只能读 ID；连接检查会逐项检测部门 ID、部门详情和一个部门的成员资料，并显示限制。自建应用须分别加入企业微信后台“打卡／审批—可调用接口的应用”，配置可信 IP 和需要的可见范围。配置存在、取得 Token、业务 API 检查成功是不同状态，不能互相替代。

四项只读检查：通讯录、应用身份、打卡权限、审批权限。检查不落入业务表、不推进同步游标；权限和字段结果只代表本次抽样。配置有未保存修改时禁止检查或同步。

Secret 使用 AES-256-GCM 随机 nonce 加密，密文保存在 `wecom_credentials`。主密钥与数据库、发布包分离：可设置 `WECOM_CREDENTIAL_KEY`（Base64 编码的随机 32 字节），否则首次保存时在 `SUXIN_PLUGIN_DATA/wecom-credentials.key` 自动生成。Windows 使用当前服务账号的 DPAPI 保护该文件；其他系统用私有目录及 0600 文件权限。升级保留插件 data 目录。备份数据库时需保留对应密钥；换机器/运行账号或主密钥需先制定重加密迁移，不能直接换钥匙。已有密文而密钥缺失、变更或密文损坏时拒绝加载/保存，不静默退回其他凭据。

配套宿主更新屏蔽企业微信配置、凭据、诊断路径的请求/响应审计正文，仍保留操作者、路径和状态。**部署网页 Secret 配置必须同时更新宿主日志脱敏代码，不能只替换旧宿主上的插件 ZIP。** 生产部署应使用 HTTPS；本地开发为 localhost。

RTC 需要可用的 LiveKit 服务及 `LIVEKIT_URL`、`LIVEKIT_API_KEY`、`LIVEKIT_API_SECRET`（至少 32 字节）。浏览器采集音视频需要 HTTPS 或 localhost 和用户授权。未配置时返回 503，不伪造成功通话。

宿主已安装并停止运行时，可执行：

```powershell
go run ./scripts/runtime-plugin-install -inspect ./dist/biz-suite.zip
go run ./scripts/runtime-plugin-install ./dist/biz-suite.zip
```

运行中的宿主请从插件市场上传安装。为普通角色同时授予“访问管理端”和需要的 `biz-suite.{hrm,im,wecom}.{read,write,manage}` 按钮权限，`manage` 包含该模块读写。IM 敏感词、表情包维护、频道创建和全局管理统计需 `im.manage`。插件不会自动向普通角色授予权限。

入口分为 **智慧HRM**（`/plugins/biz-suite/admin/hrm`）和 **企业即时通讯**（`/plugins/biz-suite/admin/im`）两个独立页面，各自只显示所属业务导航。企业微信位于智慧HRM；原 `/plugins/biz-suite/admin/wecom` 及业务详情深链接继续可用。先同步通讯录，绑定宿主部门和员工用户，再配置考勤组、审批模板控件 ID，最后回补打卡与审批。

0.1.6 同时更新宿主菜单、前端入口及插件：宿主左侧“智慧HRM”“即时通讯”打开独立页面，使用宿主登录身份完成 Cookie 交换后进入插件，不再嵌套宿主侧栏。保留旧菜单与访问权限的 ID，业务按钮授权不变；仅安装插件 ZIP 到旧宿主不能完整应用这次入口调整。


## 同步控制台（0.1.4）

- 企业 ID、应用 ID 与过滤配置保存到 `wecom_settings`，重启后恢复；保存需要 `biz-suite.wecom.manage`。同步运行期间拒绝更改配置，避免同一批次混用条件。已有企业微信原始数据后禁止直接更换企业 ID，避免不同企业 userid 冲突。
- 人员与部门均可直接填写完整中文名称，首次同步前也可配置。例如在排除人员填写“段详政”，在排除部门填写“分子公司”和“新入职员工”，勾选包含下级部门。名称精确匹配，同名人员/部门全部生效；不把名称一次性转换为固定 ID 列表，因此后续新部门、新成员会继续按规则过滤。
- 原有 ID 名单保留在高级配置，可用于精确选择某个同名对象。同一类的名称与 ID 包含条件取并集，排除任一命中优先，部门与人员条件取交集。缺少资料无法确认筛选条件时不放宽范围；没有名称不代表姓名匹配成功。
- 成功读取本次可见通讯录后，若此前已有成员未再出现，保留其最后资料与历史记录，标记范围待确认并暂停后续同步。重新同步通讯录观察到该成员后才恢复；接口失败或不完整批次不据此判定成员已离开，亦不会删除员工。
- 可直接填写中文名称，或按姓名/部门搜索选择；部门目录仍保留用于选择与宿主映射。过滤不会删除历史员工、打卡或审批；已有审批被撤销、驳回、转为待审批时仍取消其统计效力。扩大范围后可用起止时间回补历史。
- 五个独立按钮与 API：`POST /api/admin/wecom/sync/contact|checkin|leave|out|trip`（统一加插件前缀）。通讯录忽略时间，每次全量读可见范围；其他类型独立游标，时间留空增量同步。
- 请假/外出/出差各按对应 `template_id` 查询，批次和游标分开。审批模板新增 `trip`，Attendance 控件类型为 3；全部模板停用时仅复核历史审批。定时任务另执行未映射审批原始数据校验，异常列表保留待配置记录。旧 `/sync/approval` 兼容接口保留。
- 出差独立保存在 `biz_hrm_attendance_trip`，通过“出差记录”查看；月报增加 `trip_hours`。重叠时段按请假→外出→出差优先分配，合计不超过应出勤工时。

## 开发和验证

### 0.2.1 制度发布校验

点击“发布”先检查已保存草稿的生效日期、适用范围、周期与来源待确认事项；缺项会列在“发布前检查”中，通过“去完善制度”进入编辑。已有草稿未填写的日期保持为空，不自动替换为今天。完善并保存后，发布弹窗单独展示日期和范围，“确认文字”只需填写“发布”（允许首尾空格）。后端仍校验已保存制度，确认框中输入日期不会改变制度配置或绕过校验。

### 0.2.0 本地考勤核算

智慧HRM新增制度与班次、排班、计算批次、每日结果、月度核定、基准导入、加班与调休和审计记录。入口统一位于 `/plugins/biz-suite/admin/hrm/attendance-*`，后端为 `/api/admin/hrm/attendance/v2/`。所有页面采用中文表单，读写及导出沿用本人、部门、全量HRM数据权限。

实施顺序为：导入基准并确认人员关联 → 核对制度草稿、适用人员及生效日期 → 发布规则版本 → 生成或确认每日排班 → 提交后台试算 → 查看打卡与审批依据 → 填写原因和证据进行复核 → 月度复核、发布、锁定 → 导出签收表。大小周和AB班必须指定周期起点；未排班、同级冲突及证据不明确时进入待复核，不猜测出勤。

“生产一部：按实际晚间打卡切换”预置支持以下制度，创建后仍需确认适用范围和生效日期：

| 情形 | 白天工作段 | 晚间段与加班 |
| --- | --- | --- |
| 没有晚间返岗 | 08:00–11:40、13:10–17:30 | 无加班 |
| 有晚间返岗及后续下班 | 08:00–11:40、13:10–17:15 | 17:45返岗，加班从18:00开始；21:00计3小时，20:59计2.5小时，18:20计0小时 |
| 只有晚下班，缺少返岗卡 | 保留原始打卡 | 待人事复核，不自动认定加班 |

实际工作时长、核定出勤与加班分列。上述预置白天实际工时有加班时为7小时45分，无加班时为8小时；是否固定核定8小时须由人事明确配置，不根据加班数倒推。晚间17:45–18:00属于实际工作证据，但不进入加班计时。默认按每日同类加班合计后向下取整30分钟，两段20分钟计30分钟。审批交集模式只有已通过且映射到加班模板的审批有效。

8月、9月核定工作簿保留来源工作表、单元格、公式缓存和批注。重复文件幂等导入；缺工号、重复工号或姓名不一致不自动合并人员，不恢复过滤人员。基准对账分别显示核定出勤、平时加班、周末加班，缺少完整计算证据或非数值来源明确标记无法验证。部门工作时间表与企业微信规则只生成待确认草稿，不能自动成为正式制度。

已发布规则通过新版本修改。日结果保存规则、人员、原始证据和人工调整快照；试算后证据改变必须重新计算才能月结。锁定月份收到新打卡或审批撤销时仅提示差异，重开必须填写原因，旧发布版本保留。打卡旧入口区分企业微信原状态和本地判定，未计算显示“待计算”；旧月报没有正式v2结果时明确标为历史参考。

部署前备份数据库、宿主程序及插件包。程序回滚可恢复旧插件包和原程序，但不回滚数据库，不删除v5业务表及原始打卡、审计记录。密钥目录继续保留。规则尚未核对、原始证据未补齐的月份不能宣称复算通过，也不自动切换为正式月报。

打包同时生成 `dist/biz-suite-attendance.exe`，用于停服维护窗口内导入现有来源及探测/回填历史，不新增组织或启用账号。使用现有宿主配置及插件私有密钥目录：

```powershell
.\dist\biz-suite-attendance.exe -config "E:\PUTY_AI\kaoqinstyem\gosuxinwl\manifest\config\config.yaml" -plugin-data "E:\PUTY_AI\kaoqinstyem\gosuxinwl\storage\plugins\biz-suite\data" -docs docs -import-sources
# 同一配置参数下可分别使用 -probe-history、-backfill-month 2026-08；0.3.0 已停用 -wecom-rules。
```

历史探测只读取一名当前有效员工的三个单日窗口，返回零条不能证明全企业没有历史数据。回填按7天窗口复用幂等同步与日志，未启用的审批模板明确跳过；真实数据是否仍保留由接口实际响应确认。

补齐跨月班次的前后文时，可以使用 `-backfill-start 2026-07-31 -backfill-end 2026-07-31`；结束日期包含当天，最多7个已结束日期，与 `-backfill-month` 互斥。部分记录规范化失败时保留原文并继续后续窗口，最终返回非零退出码及汇总；失败数可能包含历史审批复核，应以异常列表中的独立记录数核对。

### 0.1.7 考勤审批表单展示

- 请假、外出、出差列表显示员工姓名、工号、部门及事由，支持按员工姓名搜索。姓名缺失时给出明确提示，不用内部 ID 充当姓名。
- 请假类型读取企业微信原始 Vacation 选项中的中文名称，已有编码记录无需重新同步即可显示事假、年假等；后续同步保存选项名称。缺失或歧义数据不根据编码猜测类型。
- 三类记录的详情改为审批单，展示申请人、业务状态、时间、时长、事由、目的地，以及已同步的企业微信表单和审批流程；手工记录或缺少原始表单时显示说明。当前业务状态不被原表单快照覆盖。
- 详情接口按业务记录核对审批编号及申请人，只返回展示所需字段，不返回原始 JSON。未支持的附件等控件明确提示暂未展示。

### 0.1.7 登录有效期与即时通讯保活

- 宿主会话总有效期设为 4 小时：`TokenTimeout: 13800` 与 `MaxRefresh: 600` 相加为 14400 秒，沿用宿主在最后 10 分钟内请求时续期的机制。
- 插件 HttpOnly Cookie 跟随宿主会话到期时间，修复原先闲置 5 分钟即丢失插件登录的问题；每次请求仍校验宿主会话及权限。
- 即时通讯工作空间打开且网络可用时定时检查会话，使会话可以持续续期；切换到智慧HRM或关闭页面后停止保活。主动退出、失效或权限撤销后停止保活和聊天连接，不通过旧凭据恢复已失效会话。
- 本次同时更新宿主及插件。当前本机登录缓存保存在宿主内存，部署重启后需要重新登录一次；长时间离线或系统休眠超过有效期后也需要重新登录。

### 0.1.7 人员查询与工号映射

- 打卡“人员”输入直接按姓名或工号查询，无需再次选择下拉项；同名人员仍可从下拉框精确选择。输入内容随查询和刷新保留。
- 选择部门后，人员选项只保留该部门及已勾选的下级部门人员；切换部门会清除已不在范围内的人员选择。
- 企业微信通讯录的文本扩展属性“工号”映射为员工编号；旧员工档案为空时可直接读取已保存的原始通讯录，无需重新同步。缺失或冲突属性不会清空已有工号。
- 记录文本搜索不再匹配内部员工 ID，避免内部 ID 恰好含某个工号而命中其他人员。

### 0.1.5 打卡查询与审批兼容

- 打卡列表显示员工姓名、工号及部门。人员选项按中文姓名、部门、工号搜索，同名员工仍按独立员工记录选择；未匹配员工明确提示，不用内部 ID 充当姓名。
- 支持按日、按月、自定义起止日期、人员和部门组合查询。部门来源包括企业微信与宿主，默认包含下级；按已同步成员的真实部门关系筛选，不要求先绑定宿主部门。日期按 Asia/Shanghai 解释，结束日期包含当天。
- `GET /hrm/attendance/clocks/options` 返回人员和部门选项；列表参数为 `date`、`month` 或 `start_time/end_time` 三选一，支持 `employee_id`、`department=wecom:<id>|host:<id>`、`include_subdepartments`。筛选作用于全部记录，保留分页总数；冲突或反向日期返回错误。
- 企业微信单人审批的缺省、null 或空 `batch_applyer` 数组正常转换；真实多人申请和错误结构保留为原始异常。申报时长超过起止区间的记录仍保留异常，不自动缩短时长。

## 本地测试版边界

- 前端目前是独立 ES 模块 SPA 的功能重实现，尚未完成原 Vue3 页面逐页源码迁移。当前前端差异与 IM 差异见随包文档。
- HRM 不包含上游薪资、社保、绩效和招聘等超出本计划核心考勤范围的模块。缺少有效本地制度、窗口或存在适用冲突时显示待配置及原因，不默认套用班次；不完整结果不能月结。
- 宿主用户、部门和角色保留为身份基础；0.1.8 开始按企业微信建立有所有权记录的本地组织与停用账号，不覆盖既有无关组织或账号。
- 企业微信按天审批时长、多人审批过滤、官方日报/月报与消息回调仍有待修正项，详见项目 docs/wecom-api-review-2026-10-28.txt。0.1.4 在 0.1.3 凭据配置与权限诊断基础上增加中文过滤和可见成员范围校验，不宣称上述业务审计问题已经全部修复。月报是本地规则计算，不是企业微信官方统计。
- 单元测试采用 SQLite 和模拟企业微信 HTTP 服务；前端通过真实 Chromium 与模拟接口验证名称过滤、同名对象、旧 ID 兼容、保存回显和只读权限。历史版本通过本地 MySQL 8.0.45、9880 宿主及真实 Chrome 的页面和业务回归；本轮安装后的 MySQL 网页验收以项目验收记录为准。生产数据库规模、真实租户权限、实际企业微信同步和双端 RTC 仍需部署联调。
- 本版包含 schema v1 至 v7，历史校验和保持；v5增加本地考勤版本、排班、计算结果、复核、调休和导入审计，v6、v7补充日结果、原始打卡和审批的查询索引。新增组织映射和停用账号属于宿主持久数据，插件回滚/卸载不删除这些数据。0.1.7 不识别本人/部门范围权限，回滚时这些角色无法访问HRM，不能通过补发全量read来绕开。0.1.2 回滚包不会读取网页密文，需恢复旧版环境凭据；不要删除 data 目录密钥。
